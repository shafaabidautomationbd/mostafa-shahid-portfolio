REPORT PAGE 02

Executive Management Summary

This report documents the recovery and modernization of a legacy automation and energy monitoring project that had

remained substantially non-functional since 2023. The work rebuilt the PLC/communication/SCADA chain, expanded

meter integration and advanced data handling, introduced automated recovery for unattended runtime continuity, and

then extended the restored system into a modern Node-RED, database and secure web-based Energy Management System

(EMS).

Why this work is technically significant

The assignment required simultaneous troubleshooting across industrial networks, Modbus registers, PLC data

memory, KEPServerEX, WinCC, Windows runtime reliability, Node-RED, database technical and web application

design. A fault in any one layer could break the complete data chain. The achievement is therefore not a single

software modification; it is an end-to-end modernization of a multi-layer industrial automation system.

  • Recovered broken PLC - KEPServerEX - WinCC communication and re-established live data visibility.
    • Added and engineered missing meter tags, Modbus Slave IDs, register maps, scaling and advanced data types.
      • Integrated complex Incoming-1 PQM-1000S metering into an existing legacy project without replacing the operating

      system architecture.

      • Built PLC-to-KEPServer-to-destination-PLC data paths and restored WinCC visualization of routed values.
        • Implemented an hourly self-recovery mechanism using a custom BAT file and Windows Task Scheduler to reduce

        unattended KEPServer runtime-stop risk.

        • Extended live plant data from KEPServer to Node-RED, database storage and a secure web EMS with professional

        industrial UI/UX.

        • Developed intelligent heat-identification and production-vs-electrical cross-match algorithms validated on C, A and B

        shifts.

4. KEPServer Runtime Continuity and Self-Recovery

A recurring KEPServer runtime-stop condition threatened unattended live monitoring. To prevent the EMS from

remaining offline when no operator was present, an operational self-recovery mechanism was implemented.

  • Created a custom BAT-based restart/recovery procedure for the KEPServer runtime/service.
    • Used Windows Task Scheduler to execute the recovery cycle approximately every hour, before the observed runtime-

    stop window could leave the system offline for a prolonged period.

    • Converted a manual recovery dependency into an automatic reliability function suitable for a manless monitoring

    PC.

    • Kept the solution maintainable and recoverable without changing the core PLC/WinCC application logic.

TECHNICAL CASE STUDY / PLC RECOVERY

Siemens S7-200 PLC Password & Program Recovery

EEPROM binary extraction · Password recovery · Existing program access · 1B Transformer PLC IP configuration

CASE STUDY / 01

Project Overview

This technical case study documents a PLC recovery workflow carried out on a Siemens S7-200 system. The work focused on recovering access to an existing controller project while preserving the original program and its operating logic.

EEPROM Data Extraction

  • Removed the EEPROM IC from the PLC for bench-level examination.
  • Read the EEPROM contents and saved the extracted binary data as a BIN file.
  • Kept the binary dump as a recovery artifact for analysis and verification.

Password Recovery & Program Access

  • Analyzed the extracted EEPROM binary to recover the stored PLC password.
  • Used the recovered credentials to regain access to the existing PLC program.
  • Prioritized preserving the original program rather than replacing it with a new project.

1B Transformer PLC Configuration

  • Recovered access enabled a configuration change to the 1B Transformer PLC IP address.
  • The change was performed with the intention of retaining the existing program and control logic.
CASE STUDY / 02

technical Value

This work demonstrates practical troubleshooting across PLC hardware, EEPROM memory, binary data handling, password recovery and controller configuration.

  • EEPROM-level fault investigation and binary backup.
  • Recovery of access to a legacy PLC without treating program replacement as the first option.
  • Controlled configuration change while preserving the existing project.
  • Documentation of a repeatable recovery approach for authorized maintenance work.
